## 根因与修改

原共享应用在确认消费或取消后删除可执行草稿；所有入站请求结束后，该会话不再被识别为风险交互。后续单独“确认”因此返回 handled=false，渠道转入普通 Agent。取消本身没有产生面向用户的业务回复，企业微信还会把未运行的待确认草稿当作“没有运行任务”。

本轮在公共层而非两渠道分别增加业务判断：

- `src/business/risk/state.ts`：记录轻量终态提示，只有 consumed/cancelled 原因和截止时间，不保留草稿、账户、标的、金额或结果。按已有完整业务会话键隔离。
- `src/business/risk/application.ts`：消费确认前记录 consumed，取消现有业务后记录 cancelled。后续确认给出确定性提示；不调用普通 Agent、不再次调用测算服务。取消返回统一 RiskReply。
- `src/bot/risk-adapter.ts`：展示公共取消回执，随后继续原通用停止处理。回执发送失败不会使该处理因异常而跳过。
- `src/wecom/cli.ts`：展示同一公共取消回执；有待确认草稿时，不再同时返回“当前没有运行任务”。保留对普通活跃任务的停止处理。

提示示例：

| 场景 | 新行为 |
| --- | --- |
| 确认已消费后再次确认 | “该确认已处理”，明确不会重复执行测算；失败或重新测算需重新发起 |
| `/stop` 取消待确认草稿 | “已取消风险交互”，说明草稿及排队请求已撤销 |
| 取消后再次确认 | “该风险交互已取消”，当前没有待确认草稿，不启动测算 |
| 新测算 | 建立新草稿并重新明确确认 |
| 新的普通问题 | 返回普通 Agent 路径，后续普通聊天确认不被旧终态占用 |

“已处理”只指确认已消费，不宣称测算成功。已提交给后端的只读操作可能仍在完成；没有新增物理取消保证。

## 保留范围

结束提示默认最多 2000 项，保留 5 分钟（复用状态 TTL）；重复确认不延长时间。只拦截同一业务会话内的确认词，不全局占用“确认”。新草稿替换该提示；明确进入普通聊天后释放旧提示，但使用入站捕获对象比较，迟到的旧普通消息不能清除更新的结束提示。

标记过期、容量淘汰或进程重启后不再保留原业务归属。这是有限窗口的交互提示保护，不是永久、跨重启的业务幂等账本。既有原生重投、跨用户及断线验收缺口未因此自动补齐。
