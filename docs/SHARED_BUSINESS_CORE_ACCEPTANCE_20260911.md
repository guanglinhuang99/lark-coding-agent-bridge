### 共享业务层

实际实现位于 `src/business/`，涵盖命令解析、风险查询路由、交易意图解析、字段修正、候选选择、确认、授信查询、金额单位转换、结果格式化、业务状态和进度处理。`RiskApplication` 是当前业务流程的共同入口。

原 `src/wecom/risk/` 下相关业务模块保留薄的兼容导出；它们引用相同类与函数，不是复制一份实现。Python 旧入口也委托给共享脚本。Git 的删除统计不能视为业务代码被直接删除，因为迁入的新目录在本次验收时尚未提交。

### 渠道与运行时

飞书实际消息入口在既有身份鉴权、群提及策略和持久化去重之后，先交给共享业务应用，再决定是否进入普通 Agent 路径。企业微信消息和业务卡片选择也调用同一应用。

飞书适配器不再直接依赖 Codex 内部模块；基础设施装配移至 `src/runtime/risk-business.ts`。两个渠道复用共享意图提示词、结果收集与校验逻辑。企业微信保留兼容的启动装配和渠道进程记账逻辑，通用聊天控制、平台附件处理及全部旧兼容辅助方法并未在本轮重新统一。

飞书当前通过 Markdown、选项代码和文本确认承载业务交互。未在本轮实现一套新的飞书原生按钮卡片；展示不同不意味着测算规则不同。

### 权限与状态隔离

共享业务会话键包含部署身份、渠道、会话范围和用户。共享代码不会把飞书用户 ID 与企业微信用户 ID 混用，也不会自动共享两边的确认状态或权限。

确认只允许使用服务端保存的当前草稿；重复确认、旧卡片、其他用户的状态及过期状态受校验。新请求解析失败不会重新激活旧草稿。取消后迟到的授信或测算结果不会被正常展示为成功结果，也不会恢复已取消状态。已提交的只读后端操作不保证能被物理中断，提示对此作了区分。

### 配置与打包

共同业务配置使用 `RISK_*`。企业微信兼容旧 `WECOM_RISK_*` 配置，公共配置优先。飞书权限单独使用 `LARK_RISK_ALLOWED_USERIDS` 等配置，默认不自动继承企业微信的允许名单。

构建会将共享脚本打包到 `dist/risk/direct_bridge.py`。安装版从已加载 JavaScript 所在目录解析该脚本，不再默认依赖调用者当前目录中的 `src`。显式桥接脚本配置仍优先。
