# 企业微信 workspace 切换

一个 workspace 对应一个本地目录。机器人在该目录启动 Codex，使用目录中的 `AGENTS.md` 和 `.agents/skills/<技能名>/SKILL.md`。全局技能、账号、工具和现有风险查询功能继续共用。

## 配置

原有 `WECOM_WORKSPACE` 仍为默认目录，在列表中使用 `default` 标识。不配置额外文件时保持单目录运行。

将额外工作区写入本地 JSON 文件，并通过 `WECOM_WORKSPACES_FILE` 指向该文件：

```json
[
  { "id": "review", "name": "产品审核", "cwd": "/absolute/path/product-review" },
  { "id": "research", "name": "投研", "cwd": "/absolute/path/research" }
]
```

将示例路径替换为实际存在的绝对路径。ID 使用字母、数字、短横线或下划线，不能重复或使用保留值 `default`。每个工作区须使用不同的真实目录，符号链接指向相同目录也视为重复。目录列表在启动时读取；修改配置文件后需重启机器人。正常聊天中的工作区切换不需要重启。

目录结构示例：

```text
product-review/
  AGENTS.md
  .agents/skills/
    contract-review/SKILL.md
  input/
  output/
```

## 使用

- `/workspace`：打开工作区选择卡片。
- `/workspace review`：直接切换到指定 ID。
- `/workspace default`：切回默认目录。
- `/new` 或 `/reset`：仅重置当前工作区的会话。

私聊按发送者隔离；群聊按群 ID 隔离，所有群成员共享该群的选择和会话，都可以切换工作区。一个聊天切换不影响其他私聊或群聊。

切换后收到的新消息使用新目录。已经收到、正在运行或排队的消息仍使用收到时的目录，其会话、附件上下文、风险确认状态和完成回写留在原工作区。不同工作区可各自排队，但仍受机器人的全局并发限制。旧任务的回复仍发送到原来的聊天窗口。

切回旧工作区会继续原来的会话。工作区选择和会话绑定持久化；上传附件的上下文索引沿用现有进程内存机制，重启后需要重新上传。私聊 `/resume` 只提供当前聊天、当前工作区有绑定记录的会话，不枚举其他用户或桌面端的会话。

升级前缺少工作区归属记录的待恢复任务不会自动重放，机器人会提示重新发送，避免将旧任务执行到新目录。

切换后点击其他工作区的旧控制卡片不会操作当前工作区；需要切回相应工作区或重新打开菜单。目录切换不改变共享工具和账号的权限。

## 验收

1. 两个私聊分别选择工作区，确认互不影响。
2. 同群两名成员交替发消息，确认共享工作区；另一群保持独立。
3. A 中提交任务并排队，立即切 B 提交新任务，确认各任务使用收到时的目录。
4. A/B 设置不同 AGENTS.md 和技能，确认新会话使用对应文件。
5. 切回 A，确认恢复 A 的历史；B 的重置不清除 A。
6. 跨工作区旧卡片、会话列表和附件上下文不串用。
7. 重启后确认目录选择恢复。
