公共配置仍使用 `RISK_*`，企业微信通过公共工厂的 `legacyPrefix: WECOM` 兼容对应 `WECOM_RISK_*`。公共配置优先；本轮未修改实际配置文件。

`RISK_PREWARM=0` 可关闭主动预热，但不禁用经过权限检查的按需查询；默认允许预热，且必须通过渠道提供的权限启用条件。`RISK_INTENT_MODEL` 使用公共解析模型设置。新增的 `RISK_INTENT_TIMEOUT_MS` 默认 180000，`RISK_INTENT_EXIT_GRACE_MS` 默认 5000；相应数值必须为正整数。通用聊天的模型和退出设置仍由其原有配置负责，不等同于风险解析专用配置。

两渠道允许名单继续独立。配置未就绪、后端路径不存在或权限未开放，不应被描述为已具备线上业务可用性。

## 复现并修复的关闭竞态

检查真实 RiskDirectClient 实现时发现：ensureStarted 会将 closing 重置为 false。客户端已经 close 后，显式 prewarm 或迟到的内网探测仍可重新启动 Python。

先添加回归，实际得到三项失败：关闭后 prewarm 成功；关闭后迟到的探测使产品查询成功；同样使持仓查询成功。测试使用正式客户端代码与模拟子进程、模拟网络探测，没有启动真实 Python 后端。

修复在客户端探测、缓存读取及启动边界检查终止状态，并移除关闭状态重置。明确 close 后不可重新打开；启动超时或非关闭的异常退出仍保留原有恢复能力。三个新用例与原有超时、缓存、重试用例均通过。
