## 真实 benchmark 矩阵

| 场景 | 关键观察 |
| --- | --- |
| 严格标准交易首次请求 | 分开记录 Python 启动/导入、数据库初始化与首次应用缓存缺失 |
| 同一客户端重复交易 | 缓存命中、AI/查询调用次数；正式测算仍实际执行 |
| 自然语言交易 | 原 AI 回退、意图正确性、实际模型耗时 |
| 仅修改金额、仅修改回购期限 | 单字段修改准确、再次确认、测算输入完整 |
| 复合修改、证券名称及歧义候选 | AI 回退或候选选择，不能跳过用户确认 |
| 普通查询 | 产品、候选查询正确；持仓/风控结果保持实时调用 |
| 8 并发同查询和不同查询 | 调用合并范围、吞吐、排队、错误率及延迟 |
| 超时、排队取消、客户端关闭 | 过期任务不启动；运行中后端任务占位直到结束 |

每个正常性能场景建议至少 30 个可用配对样本。昂贵冷启动若样本不足，注明实际数量。按 AB/BA 交错顺序运行，控制数据库缓存的先后偏差；不能为了“冷启动”清空共享生产缓存。

每个样本记录版本、场景、UTC 时间、匿名用例 ID、数据日期/版本、缓存状态、成功/失败及错误类别、AI 次数、各后端方法次数、总时间与阶段时间。阶段至少包括启动、AI、准备、证券候选、测算、排队、展示；无法观测的项写“未观测”，不能记作 0。人工确认等待单独记录并从机器处理耗时剔除。不要把敏感凭证、原始提示词或完整持仓写入 Git。

汇总 N、成功率、median、nearest-rank P95、绝对时间变化和百分比；失败/超时单列，不能悄悄剔除后只报成功样本。减幅按 1 − 新版中位数 / 旧版中位数计算。

## 业务一致性与交互验收

固定产品、证券、买卖方向、金额及单位、期限、市场、持仓日期、净值和台账版本。核对规范化输入、测算前后数值、限制阈值、通过/不通过及提示内容。名称与时间戳等展示差异分开记录；数值精度容差应依据原有业务规则，不能为了通过而放宽。无法固定的数据变化逐项注明，不能全部归因于补丁。

特别覆盖负数、含糊金额、证券名称/代码混用、一级申购证券标识、复合修改回退、重复确认去重、候选选择和确认状态过期；核对旧进度不会覆盖最终结果。真实平台收发尚未验收：先完成本地链路，只有取得测试机器人或测试会话的明确收发授权后才能做平台测试，不启用同一 Bot 身份的第二实例。

当前后端不支持运行中协作取消：cancel 只能取消排队任务并抑制迟到输出，已运行调用会继续占用槽位直到完成。不要据此声称实现了中断数据库执行。
