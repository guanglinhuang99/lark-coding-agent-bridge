# risk-service 本地直连测试记录（2026-09-02）

## 结论

WeCom bot 已停止调用 risk-service MCP，改为通过项目根目录的 `risk-service`
软链接加载 risk-service Python 源码，并由一个常驻 Python 进程直接执行。风险快速路径仍不调用
Codex，因此 AI token 使用量为 0。

在与旧记录可比的 9 个已完成测算场景中：

- 旧 MCP 测算阶段平均 33.181 秒；本地直连首次轮平均 16.948 秒，下降 48.9%。
- 常驻进程和缓存预热后平均 5.601 秒，较旧 MCP 记录下降 83.1%。
- 旧记录中的正回购在 60.005 秒超时；本地直连首次 3.889 秒、热缓存 2.490 秒，均成功。
- 本地桥接层在后端 `end_to_end` 以外的平均开销约 36 毫秒，已基本消除 MCP HTTP、鉴权、工具发现及轮询开销。

该对比同时包含此前已实施的 risk-service 缓存/并发优化和本次 MCP 移除，不能把全部降幅仅归因于传输方式；但最终用户可感知耗时可直接与旧记录比较。

## 仍可继续优化的耗时

热缓存轮中，主要剩余时间已不是本地桥接层：

- 每笔测算的 `setup` 平均 2.490 秒，主要是产品和最新持仓日期准备。
- 证券候选查询平均 2.412 秒。
- 买入场景的 `scenario_resolution` 约 3.2–4.6 秒。
- 本地桥接层额外开销平均约 36 毫秒。

后续若继续提速，优先考虑短 TTL 缓存“产品最新持仓日期”，以及把路由阶段已经选中的证券详情传给测算阶段，避免再次解析同一证券。冷启动还可在 bot 启动后异步预热产品台账和 Pins 数据；这些优化需要同时保留数据日期和证券状态的新鲜度边界。
