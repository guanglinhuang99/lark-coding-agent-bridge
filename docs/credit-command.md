# /授信

示例：`/授信 宁德时代、赣锋锂业、天齐`。支持中文/英文逗号、顿号、分号和换行分隔；公司名称中的空格保留。无名称时显示用法。

查询使用现有风险权限和会话队列，直接访问授信服务，不调用模型，不消耗或修改待确认交易。附带附件时仅查询命令中列出的名称。

返回七列：授信主体、集团内授信、集团内已用、集团内剩余、三方授信、三方已用、三方剩余。每个主体一行，金额为万元。持仓使用 PQ 最新可用日期（包含当天）；整批统一日期。全名匹配优先，模糊名称命中多个主体时全部列出并标注匹配关系；重复主体去重。

额度未配置时显示“未配置”，无法计算的金额显示“—”。沿用原后端剩余额度最低为零的规则，超额占用另外标注主体、类别及金额。未知主体、匹配过多或查询失败明确提示。每次最多 50 个查询名称、每个名称最多 200 字；整批最多返回 50 个主体，超过上限的查询词会提示缩小范围；结果按完整行和 UTF-8 消息长度分段，重复表头。

后端依赖：配置的 `WECOM_RISK_SERVICE_DIR/credit_query.py` 必须提供 `build_credit_reports`。桥接方法为 `get_credits`，参数为 `entities: string[]`，返回 `date`、`amount_unit`、`reports`、`unmatched`、`errors`。原 `get_credit` 单主体调用保留。

本次代码修改后需重新启动机器人及其 Python 子进程才能加载新命令；构建不等于服务已重启。

验证：WeCom 单元测试、TypeScript 检查和构建通过；`tests/python/test_credit_backend.py` 隔离数据库和框架依赖，验证实际授信模块的批量匹配、日期刷新、金额组装及失败语义。当前配置的 Python 缺少完整服务测试依赖，尚未完成真实数据库查询和企业微信端实测。
